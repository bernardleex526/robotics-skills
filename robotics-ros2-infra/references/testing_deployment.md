# ROS 2 测试与部署边界

## 测试分层

1. **纯逻辑单元测试**：消息转换、状态机、参数校验，不启动 ROS graph。
2. **节点测试**：用固定输入检查 publisher/service/action 与 QoS 契约。
3. **launch_testing**：启动最小节点图，验证 lifecycle、命名空间、TF owner 和退出行为。
4. **录包回放**：用 rosbag2 固化时间戳、丢包、异常值和退化场景。
5. **SIL/HIL/真机**：分别记录允许的执行器连接范围与安全门槛。

测试通过只能证明覆盖的输入和环境。daemon 启动、节点出现、lifecycle active 或 HTTP 请求成功，
都不是端到端任务成功的充分证据。

## 部署

- 固定 ROS 发行版、RMW、依赖锁和配置版本。
- systemd/容器服务设置启动依赖、健康检查、资源限制和有界重启策略。
- 不把容器 `--privileged`、host network 或设备全量映射当成默认配置。
- 保存上一稳定包和配置，回滚演练必须包含数据格式/参数兼容性。
- 日志、metrics 和 tracing 使用有界存储，避免磁盘写满拖垮控制。
- 重启后不能自动恢复危险动作；是否恢复任务由上层状态机和风险分析决定。

## 安全与安全性

SROS2/网络 ACL 保护身份、机密性和授权，不提供机械功能安全。反过来，硬件安全链路也不能替代
软件供应链、凭据管理和远程接口最小权限。两类控制需要分别设计和验证。
