# 激光惯性里程计：工程参考

## 输入与 deskew
明确 t_point = t_scan + scale * offset 的来源；有的驱动使用绝对时间，有的使用扫描开始/结束相对时间。不能按字段名猜测单位。记录是否已由驱动去畸变，防止二次补偿。
查 IMU 是否覆盖整个扫描积分区间；不要静默外推缺失区间。重力、加速度单位、轴向、四元数约定和角速度饱和分别核对。把 IMU 与雷达坐标变换的方向写成 T_target_source。

## 故障实验
- 静止漂移：检查 bias 初始化、振动、重力模型、错误外参；不要用静止一段数据证明动态标定有效。
- 转弯重影：分别扫时间偏移和外参的小范围候选，观察独立回放集，避免同时改变多个变量。
- 长廊/地面退化：检查几何约束方向及残差/状态一致性；低残差也可能欠约束。用轮速、视觉或 GNSS 的收益须与新增相关性和故障模式一起评估。
- 地图越来越慢：分开测邻域搜索、地图维护、发布、记录和优化，而不是只测主更新函数。

## 验收与复用
记录按路线分段的 ATE/RPE（含对齐方式、关联容差）、tracking lost、重置次数、地图厚度、p95/p99 延迟与内存。不要给纯里程计宣称全局一致地图。
选型先核验候选项目当前传感器支持和维护状态；名字相同的 fork 不等于原作者支持。

## LiDAR-视觉-惯性联合链路

RGB 与 LiDAR 联合并不只是彩色投影：明确视觉测量是否进入状态更新、摄影测量模型、遮挡/曝光变化与同步误差如何处理。分别做 LiDAR-only、visual-only（如模型支持）和联合 ablation，不能从着色点云推断视觉提高了定位。
外参、点时间和相机曝光参考时刻组成一条契约；将重建贴色误差与轨迹误差分开。可检索作者实现 FAST-LIVO2、R3LIVE 作为候选，当前维护、许可和 ROS 接口仍须重新核验。

- https://github.com/hku-mars/FAST-LIVO2
- https://github.com/hku-mars/r3live
